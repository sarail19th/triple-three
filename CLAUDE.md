# Triple Three (emoji)

Single-file merge-puzzle game (a free hobby project inspired by the classic genre, with its own name, code and emoji art): 6x6 board, place the "next" item, 3+ orthogonally connected identical items merge into the next tier on the tapped tile, bears wander and get trapped into tombstones -> churches. Plain HTML/CSS/JS, no framework, no runtime deps, installable PWA. Spec: `docs/GAME_BRIEF.md`.

## Layout
- `src/logic.js` - pure game logic (UMD: `require` in Node, global `TT` in the browser). State is plain JSON: `{ver, wild, map, w, h, land[], top, grid[w*h], cur, next, hold, score, coins, stock, milestone, turn, over, rng, seed, undo}`. `place(state, idx)` -> `{state, events}` or `null`; `swap`, `undo`, `validate`, `preview` (pure what-if for a placement), shop: `buy(state, item)` -> state, `hammer`, `trap` (kills a bear or fox into a tombstone), `move(state, from, to)` (mover: carries one non-animal item to an empty tile and merges it there; `previewMove` is the pure what-if), `buyLand(state, side)`, `open` (collect treasure/cash) -> `{state, events}` (all free actions, cost coins; prices/earnings in `PRICE`/`COIN`/`LAND_PRICE`). Everything is deterministic from `seed` (mulberry32; its state lives in the game state so undo/replay is exact). The board size is per state: the module-level `W/H/N` are set by `dim(state)` at the top of every public function (the exported `W/H/N` are only the starting 6x6).
- Codes: 0 empty, 1-10 building chain (grass, bush, tree, camp, hut, house, village, school, hospital, mall), 11 cash (final; tap to collect `CASH_COINS`), 12 bear, 13 tombstone, 14 church, 15 cathedral, 16 crystal, 17 treasure (final; tap to open for `TREASURE_COINS`), 18 fox, 19/20 a growling / angry bear (Wild bears games only; use `TT.isBear(code)` for "is a bear", never `=== TT.BEAR`), 21 water (map tile, see Maps). Use the named exports (`TT.BEAR`, `TT.CHURCH`, ...) in code and tests, never the numbers.
- `src/game.js` - UI: placement (Preview toggle, `tt-preview`; mouse: hover previews and ONE click places; touch: tap to preview, tap again to confirm), reserve tray (left of Place, the swap slot), shop (scrollable item row built by `buildShop`, trap/hammer/land row), hammer mode, one-level undo (there is no hints feature any more), animations driven by the `events` list, ambient critters (decorative only, never in the state; each critter is bound to ONE tile and only wanders inside it, re-homed on another matching tile if its tile vanishes), localStorage save (`tt-save`) and best score (`tt-best`). The board is rebuilt when `state.w/h` change. `#seed=N` in the URL forces a reproducible game. `window.ttDebug` is a read-only hook for tests.
- `src/style.css`, `src/index.html` - templates with `/*INLINE_...*/` placeholders.
- `build.js` - inlines everything into `dist/index.html`, writes manifest + service worker (cache name = content hash).
- `gen/icons.js` - PWA icons into `dist/` (pure Node PNG writer, no Pillow).
- `test/test.js` - logic tests + 400-game random fuzz (state valid after every turn, games terminate).
- `test/ui_test.py` - Playwright mobile-viewport test: PWA checks, plays seeded random turns (with swaps/undos) to game over, asserts valid state and DOM == state after every action.

## Commands (run from the project root)
```
node test/test.js          # must print "OK: N logic tests passed"
node build.js              # dist/index.html (self-contained) + manifest + sw.js
node gen/icons.js          # icons into dist/ (run after build)
python test/ui_test.py     # needs: pip install playwright && python -m playwright install chromium
                           # (preinstalled-browser setups: TT_CHROMIUM=/path/to/chromium python test/ui_test.py)
```
Serve `dist/` over https or localhost for the service worker (`python -m http.server -d dist`); opening the file directly also works but skips the PWA parts.

## Rules when changing things
- Changing logic: `node test/test.js`, rebuild, `python test/ui_test.py`. Keep `validate()` in sync with any new invariant.
- All randomness must go through the state's `rng` (never `Math.random` in logic) or replays/undo break.
- Decisions the brief left open: crystal acts as the best item kind that merges where dropped, otherwise waits as a wildcard; mall trio -> cash (final tier, collectible); bears and foxes come only from the item queue; one-level undo (costs coins); swap is a free action.
- Shop/coins: merges pay `(group-2)*COIN[tier]`; `buy` makes the item current and pushes the old current to `next` (old next is dropped); `hammer` clears any tile. `buy` refuses a purchase that would leave a full board unrescuable.
- Crystal choice (`crystalTier`): every kind the crystal could stand in for that makes a 3+ group is played out on a scratch copy INCLUDING the cascade (a camp trio makes a hut that may join two huts into a house), and the kind with the most points wins (then coins, then the `CRYSTAL_AS` order). It is not 'highest tier first'.
- Crystal: a crystal that cannot merge when placed stays as a wildcard and is re-checked after every placement (`settleCrystals`); `validate` asserts no crystal is left that could merge. A group of 4+ merges all its members into ONE next-tier item (only points/coins scale with size). Three or more connected crystals that have no tier to stand in for merge into ONE treasure on the tapped tile (`resolveAt` special-cases `CRYSTAL`; it pays no points or coins, the treasure is the prize; `validate` flags an unmerged gem trio and `migrate` settles every save).
- Shop limits: `stock` per item (`START_STOCK`; crystal starts at 0), each purchase/hammer/trap uses one; score milestones (`MILESTONES`, `milestoneScore(n)`) add `RESTOCK` and emit an `unlock` event. Game over = full board and no usable hammer (coins >= price AND stock > 0). Undo costs `UNDO_COST` coins, taken from the restored snapshot (`canUndo`). The snapshot (`state.undo`, one level) is taken by `place` AND by `move` / `hammer` / `trap` (`snapshot(state)`), so Undo reverts the last placement or the last mover / hammer / trap use (a tool use replaces an older placement snapshot); other free actions (buy, land, bridge, pond, bank, loans) do not take a snapshot and are reverted only together with the step before them. Old saves are upgraded by `migrate()`.
- Crystal can stand in for the bear chain too (cathedral > church > tombstone, then mall..grass); it is re-checked after placements, bear moves and traps.
- Bear trapping is per pocket (connected area of empty cells + bears, see `moveBears`): a bear dies only when its whole pocket has no empty cell, so bears sharing a pocket with room never die (a boxed-in one waits for its neighbour to move). When trapped tombstones merge, the cell just played goes first, so the church forms where the last bear was placed.
- Building chain (v2): 🌱 🌿 🌳 🏕️ 🛖 🏠 🏘️ 🏫 🏥 🏬 -> 💵 (collectible). Points x3 per tier, coins ~x2 per tier. Old (version-1) saves have other codes: `migrate()` remaps them (`V1_CODE`) and settles groups that the old final tier left unmerged. New state fields need a `migrate()` default and a `validate()` check; `migrate()` also fills any `START_STOCK` key a save lacks, so new shop items never invalidate a live save.
- Animals (`moveBears`): trapping is per pocket (connected empty cells + bears + foxes). A pocket with no empty cell turns every bear AND fox in it into a tombstone: a fox walled in on all sides, cornered, or sharing a box whose last free tile was just filled, and a fox on a full board all die the same way. A fox that is not trapped never walks, it warps to a random empty cell anywhere that still leaves it room (`landsWithRoom`: a warp never lands in a hole that would trap it at once; sealing it in later is the player's doing). Trapped animals on the same turn merge starting from the cell just played. The trap item kills a bear or fox anywhere.
- Shop pricing: `stock` per item; while it lasts the price is `PRICE`, past zero it doubles for every purchase (`priceOf`; stock goes negative = debt, milestone restocks pay it back). Hammer/trap/mover just run out (mover: `PRICE.move`, stock 1, +1 per milestone, free action, cannot carry bears or foxes, its drop merges like a placement). A building tier above tree is sold once one has stood on the board (`state.top`, `unlockedTop`); the crystal needs the first milestone. Restocks skip tiers that are not unlocked yet.
- Land: `buyLand(state, 'top'|'bottom'|'left'|'right')`, each side once, `LAND_PRICE` rises, adds one row/column (indices shift, so never cache cell indices across a land purchase). The new strip is empty land except where the old edge tile next to it is water (or a bridged tile): there the water carries on, so a river keeps running off the map. A strip can therefore add no free tile, so `buyLand` recomputes `over` with `isOver`. Game over = full board, no usable hammer AND no affordable land. Undo reverts a land purchase made since the snapshot (and refunds it).
- Name: the game is called Triple Three (renamed from เกมสามหมี / Three Bears at the owner's request). Keep the name consistent in UI, manifest, docs, comments and the service-worker cache name; do not use the name of the original game it is inspired by.
- Service worker is cache-first; the page reloads once when a new version takes over. After a rebuild, hard-refresh (Ctrl+Shift+R) to see changes.
- Icons are chosen by the owner (the plant tiers 🌱 🌿 🌳 are the summer look and change with the season, see Seasons): 🌱 🌿 🌳 🏕️ 🛖 🏠 🏘️ 🏫 🏥 🏬 💵. Do not swap similar-looking ones (🏡 looked too much like 🏠).
- Roadmap notes (bank, locked tiles, calendar, pond-style dead tiles) are in `docs/IDEAS.md`.
- The board is one plain grass field (continuous texture on `#board`, transparent tiles, faint tile edges). Do not bring back the alternating checkerboard tint.
- Animals on/off (per game, `state.bears` / `state.foxes`, both default true; chosen in the New game dialog (Bears: Classic / Wild / No bears; Foxes: on / off), remembered in `tt-bears` / `tt-foxes`; old saves get both true in `migrate`): `drawItem` turns a switched-off animal's draw into grass (same rng draws, so games with both on replay exactly as before). `wild` is only ever true with bears on. `validate` rejects a switched-off animal on the board / in cur-next-hold, and graves when both are off (calm mode). The trap tool is hidden in calm games (and its tour step skipped). Best scores get `-nobears` / `-nofox` suffixes. `startNew(seed, {wild, map, bears, foxes})` in game.js.
- Wild bears (per-game option, `state.wild`, chosen in the New game dialog, remembered in `tt-wild`; classic games and every old save are `wild: false` and never see codes 19/20, `validate` enforces it; best scores are separate: `tt-best` / `tt-best-wild`). A bear that cannot step because it is boxed in while its pocket still has room (a sealed bear still dies at once) escalates: boxed 1 turn -> 19 growling, 2 turns -> 20 angry, the 3rd boxed turn it mauls ONE adjacent tile of tier 1..`MAUL_MAX` (grass..hut) one tier down (grass is destroyed = an escape hole; the lowered tile merges if it completes a group) and starts over as a calm bear (12). A bear that walks resets to 12. Houses and everything above, tombstones, churches, cash are never mauled. The stage lives in the cell code, so no per-bear counters are stored.
- Wild bears also breed (`breed`, called from `moveBears` in wild games only): a pocket of at most `BREED_MAX_POCKET` (6) tiles holding 2+ bears and 2+ empty tiles has a `BREED_CHANCE` (10%) each turn of a calm cub appearing on one of its empty tiles, so a cub never takes the last free tile; never more than `BREED_MAX_BEARS` (8) bears on the board. Crowded pens are what makes bears wait boxed in long enough to maul.
- Highlands (`state.map === 'highlands'`; codes 24 `MOUNTAIN` ⛰️ and 25 `HOLE` 🕳️, `LAST_CODE`, `isTerrain(code)` = water / seized lot / mountain / hole; `state.leveled`; `levelSpots`, `levelPrice` 150 x1.25 rounded to 10, `canLevel`, `buyLevel`, `fillCount`): `highlands(s)` scatters 4..6 mountains and 3..5 holes with the rng. Both are walls for animals (`roaming` ignores them, so pockets are sealed by them), not hammerable, not movable (`isTerrain`, so the hammer button stays off when only terrain is left). A mountain cannot be placed on; the shop tool `#levelBtn` (`data-tool="level"`, mode `'level'`, hidden when no mountain is on the board) flattens one for coins, a free action. A hole is a legal `place` target for ANY item (even a bear or a bank): the item is used up (event `fill`, no merge), the tile becomes EMPTY and a turn passes, so a hole is a place to play (`isOver` also needs `fillCount === 0` and no affordable level; the UI note 'Board full' too). `preview` of a hole returns `{fill: true, final: EMPTY}`. The tour has a Level step (`when` the button is visible); the New game map cards are a 3-column grid (`.opts.six`). Look (owner's choices, keep them): a mountain has NO tile behind it, just its emoji ⛰️, and `em()` shows the snow-capped 🏔️ (plus a white CSS glow) in winter. A hole has no emoji (the CSS hides it, the text stays for tests and screen readers): like the water, holes are ONE soft SVG layer (`drawTerrain` in game.js, `svg.terrain`, cached by `terrainKey`) above the water layer and under the tiles, where neighbouring holes fuse into one sunken pit with a raised ridge round it, an inner wall in shade, a deep middle and jagged cracks running out across the floor (deterministic per tile), running on past the board edge. The colours are SEASON tokens (`--h-rim` ridge, `--h-lip` inner wall, `--h-out` floor, `--h-in` middle, `--h-crack`; owner's brief): summer and spring a green sunken patch with dark green cracks, autumn a brown cliff / sinkhole with a sandy ridge, winter a pale blue ice hole with a white ridge and blue cracks. The layer reads them through `style="...:var()"`, so a season change recolours it without a redraw; the New game thumbnails paint holes as `.mini span.o` from the same tokens.
- Island (`state.map === 'island'`; `state.reclaimed`; `reclaimSpots`, `reclaimPrice`, `canReclaim`, `buyReclaim`, `MAX_RECLAIM` 48 = the board minus the smallest island, `RECLAIM_PRICE` 60 rising x1.1): the shop tool `#reclaimBtn` (`data-tool="reclaim"`, mode `'reclaim'`, hidden on other maps) turns a natural sea tile that touches a land tile (not water / seized / bridged; never a dug pond) into EMPTY ground, a free action like bridge / pond; glowing `.spot` tiles show where. `isOver` also counts `canReclaim` (a full board with coins for the sea is not over). Bridges are never offered on the island (`bridgeSpots` returns []). Lake quests there count only the ponds you dug (`lakeGrid` ignores the natural sea), otherwise two ponds beside the sea would pay a 2x2 lake. Saves from the first island version (a ring of sea round a full 6x6 field) stay valid. `migrate` defaults `reclaimed` 0, `validate` allows it only on an island (and requires the 8x8 size); the TOUR has a Reclaim step (`when` island) and the Land step is skipped on the island. The miniature cards set their grid size from the generated board (`miniMap`, 8x8 for the island).
- Treasury (`tt-treasury` in localStorage = `[Bank 1, Bank 2, Bank 3]` account balances, NOT in the game state; `TT.deposit(state, bankIdx, amount, balance)` -> `{state, net, fee, rank}`, `TT.withdraw(state, bankIdx, amount, balance)` -> `{state, taken, rank}`, `treasuryRank(state, bankIdx)` = the bank's place in `bankOrder` (0..2) or -1 when the cell is no bank, `treasuryNet`, `TREASURY_FEE` 5%, `TREASURY_BANK_CAP` 1000000 PER ACCOUNT; `state.boost` = total coins this game has withdrawn): every bank has its OWN saved account, named by the order the banks were built (Bank 1 / 2 / 3, the labels the bank dialog already shows), so three banks hold up to 3M in all and a game with one bank can only reach Bank 1's account (hammering or moving the first bank shifts the order, the accounts follow the rank, not the tile). The Bank dialog (`renderTreasury`, uses `bankAt`) deposits into / withdraws from ITS account only (¼ ½ All). `accounts()` in game.js reads the storage: an old single number (earlier versions) is poured into Bank 1's account first, then 2, then 3. Deposit takes `amount` coins out of the game, the account gets `amount - floor(amount * fee)` and must have room; it is refused for a game that would be stuck afterwards (`isOver`). Both are free actions that set `state.undo = null` (the accounts live outside the state, so an undo would copy coins). A game with `boost > 0` has its own best-score board (`-boost` suffix) and `modeLabel` says 'treasury coins'. The game-over card shows the total of the three accounts (`#overTreasury`). `deposit` / `withdraw` never create coins (tests check the game coins + account total). There is no automatic saving on leaving a game and no 'take at start'. Interest: a paying bank (no defaulted loan) also pays `floor(vault[rank] * speed * TREASURY_INTEREST_PPM / 1e6)` coins per turn on ITS OWN account (`TREASURY_INTEREST_PPM` 300 = 0.03% a tick, about 4% a year of 120 ticks; whole-number maths because 0.0003 * 100000 is 29.99... in floating point), on top of the flat `bankIncome`; the `bankpay` event carries `interest` (one number per paying bank, parallel to `at`) and `coins` is the total. `state.vault` = [Bank 1, 2, 3] is a MIRROR of the saved accounts so the logic can compute it: `deposit` / `withdraw` keep it in step, the page refreshes it from `accounts()` in `startNew` and right before every placement (`doAction`), so a stale copy after Undo or a reload never matters; `migrate` defaults `[0,0,0]`, `validate` checks 3 ints within the cap. The bank dialog shows the interest on its account. `migrate` defaults `boost` 0.
- Quests, achievements and titles (game.js: `TITLE_INFO`, `ACHIEVEMENTS`, `STAT_KEYS`, `stats` / `statsNow` / `viewStats`, `allQuests`, `questDone`, `checkEarned`, `addStat`, `setMax`, `trackEvents`, `trackState`; `tt-stats` = the counters saved across games AND regions, `tt-earned` = the quest ids already announced, `tt-title` the pick; screen `#quests` opened by `#questsLink` (page 1 Titles, page 2 Achievements, progress bars)): a quest is done when its counter reaches its goal. The counters: `bears` and `foxes` live in the game state (`state.bearsTrapped` / `state.foxesTrapped`, counted in `moveBears` and by the trap tool, so undo takes them back) and are added to `tt-stats` when a game is left (`startNew`; the New game dialog and the quests screen already include the game on screen); the rest are counted from the events as they happen (`trackEvents` in `render`: open -> cash / treasures, merge into a church, repay, reclaim, level, fill, pondpts, lake size 4) or from the game as it stands (`trackState` in `save`: best tier, coins, bank, long bridge, all three bank accounts full = `gold`) or derived (`regions` = open regions of the world). `checkEarned` announces what was just completed (queued in `news`, shown by `animate`, because `animate` clears the effects layer); the very first run records what is already done silently. FOUR quests are TITLES (`TT.TITLES`, effects in the logic; `state.title` '' or an id, picked per game in the New game dialog `#titleOpts`, only if earned; a `#seed=` link never applies one; a game with a title has its own best-score board, `-<id>` suffix, and a `modeLabel`): `hunter` Bears Hunter (100 bears; `bearCut` 0.3: that share of bear draws turns into grass), `hawkeye` Hawkeyes (25 foxes, `foxCut` 0.5, the same for foxes; foxes are rabbits in winter), `tides` Master of Tides (the 4x4 lake = event `lake` size 4; `luckyBonus` 0.08 and `luckyMaxTier` 7 in `luckyTier` on `WATER_MAPS` medium / hard / island, where Hard had no lucky drops at all), `gold` Gold Keeper (3 banks, all three accounts at the 1M cap in one game; `noFee` = `treasuryNet(amount, title)` charges 0 and `interestX2` doubles the account interest). A title's extra rng draw only happens when its cut exists, so a game without that title replays exactly as before. To add a quest: a row in `ACHIEVEMENTS` and a counter in `STAT_KEYS` + `trackEvents` / `trackState`; to add a title: `TT.TITLES` (stat, goal, effect), its hook in the logic, `TITLE_INFO` in game.js and a line in How to play. The New game buttons (`.dlgbtns`) are sticky at the bottom of the scrolling dialog.
- World (UI layer only, NO logic change: every region is a normal game; `REGIONS` in game.js, `region` = the active id or '' for the free game, `tt-region`, `tt-world` = `{tops: {id: best building tier}}`, `saveKey(id)`, `regionOpen`, `enterRegion`, `buildWorld`, `noteWorld`, `#world` / `#worldGrid` / `#worldLink` / `#worldFree`): a 3x3 grid, the owner's layout: the calm Meadow in the middle (`easy`, no bears, no foxes), four side regions in classic mode (Orchard `standard`, River Bend `medium`, Highlands `highlands`, Isle `island`), four corners with Wild bears (Thornwood `hard`, Black Marsh `medium`, Crag `highlands`, Atoll `island`). Each region keeps its own save slot `tt-save-<id>` (the free game keeps `tt-save`, the normal New game with any map), so switching saves the game on screen in its slot and loads or starts the other (`enterRegion`; `startNew(..., {noBank: true})` so a game that is only left behind is not counted into the title stats twice). Unlocking: the Meadow is open; a side region opens when the Meadow has reached tier 7 (a village, which is also what unlocks banks), a corner when EITHER neighbouring side region has reached tier 8 (a school) (`needs` / `need` per region); `noteWorld` (called by `save`) records the best tier per region in `tt-world` and queues a toast (`worldNews`, shown by `animate` because it clears the effects layer) when something opens; once open stays open. The treasury accounts and `tt-stats` are shared by all regions (that is the connection: coins earned in the Meadow, deposited at a bank, can be withdrawn in a corner). Best scores get a `-r-<id>` suffix (`bestKey`). The world is the front door: a brand-new player (no `tt-save`, no `tt-region` ever stored) starts in the Meadow (`region` initialiser + the boot code), while a player who already has a game keeps it as the CUSTOM GAME (`region === ''`, the normal New game dialog with any map and animals, the old `tt-save`; the button in the world screen is `#worldFree`, 'Custom game'). `ui_test.py` pins `tt-region` to `""` through an init script (unless `tt-test-fresh` is set, which the fresh-install test uses). In a region the New game button only restarts it on its own map (`#dlgSetup` is hidden, the dialog says 'Restart <name>'; Play again also keeps the region); a `#seed=` link switches to the free game. The seed line shows the region name and icon, the tour has a World step, How to play has a World line (maps page), and the cards reuse `miniMap` with `SAMPLE`-style fixed seeds (`seed` per region).
- Maps (`state.map`, chosen with the bear mode in the New game dialog, remembered in `tt-map`; best scores are per map and mode: `tt-best` for easy+classic, `tt-best-<map>[-wild]` otherwise): `easy` plain field (uses NO rng, so classic seeds replay as ever), `standard` 5 random grass/bush/tree that never form a group, `medium` a fixed winding river (`MEDIUM_WATER`, splits the field in two until a bridge exists), `hard` three random ponds (6..9 water tiles, the land stays one connected piece; the rng draws make them reproducible per seed), `island` the biggest board (8x8, `ISLAND_SIZE`, all four `land` sides already bought, so `buyLand` is refused and the land buttons are hidden), all sea except a connected random island of `ISLAND_MIN`..`ISLAND_MAX` (16..20) tiles inside the middle 6x6 (the generator uses the rng, so the shape is reproducible per seed; see Island). Water (code 21) is just a wall: not EMPTY (so it never counts as a free tile or a landing spot), not hammerable, not movable, not mergeable, animals cannot enter it; land purchases keep it (indices shift). Old saves are `easy`.
- Queue balance: `WEIGHTS` grass 61 / bush 16 / tree 6 / bear 12 / crystal 3 / fox 2; the crystal costs `PRICE[16]` (300; it was 50 at 4%, then 750 at 2%, which the owner found too dear and too rare). `drawItem(s, events)` also rolls `TRAP_DROP` (3%) on real turns (only when `events` is passed and the game has animals): +1 `stock.trap` and a `bonus` event (UI toast). The roll is an extra rng draw per turn, so queues differ from games made before this change (saves are unaffected: they store the state).
- New game sample maps: each map card (`.mapcard`) holds a `.mini` 6x6 thumbnail built by `miniMap(map, seed, el)` from the REAL generator (`TT.newGame(seed, {map})`, fixed seeds in `SAMPLE_SEEDS` / `CARD_SEED`), and `#mapSamples` lists examples of the selected map (3 for Standard / Hard, 1 for the fixed Easy / Medium / Island). When a map type is added, add its seeds and note.
- Lucky drops (`luckyTier`, inside `drawItem`): once `state.top` is at least 5, the next item is sometimes a camp / hut / house (tier 4 up to `min(top-1, 6)`, weights 3:2:1 for lower tiers first) with `LUCKY_RATE` per map (easy 6%, standard 4%, medium 3%, hard 0). The extra rng draws only happen when a drop is possible, so early games and the whole Hard map draw exactly the sequence they always did.
- Water look: the blue is ONE soft SVG layer under the tiles (`drawWater` in game.js: blurred + thresholded rects so neighbouring water tiles fuse, corners round off, a sandy bank blends into the grass, ripples drift; water touching the board edge is extended past it so rivers run off the edge). The water tiles themselves are transparent and only refuse taps. Swans and fish are critters bound to water tiles like the other critters.
- Bridges (`state.bridges`: indices of bridged water tiles; `bridgeSpots`, `buyBridge`, `bridgePrice`, `canBridge`): a shop tool, a free action; the button (`#bridgeBtn`) is only shown while a spot exists or a bridge has been built (never on maps without crossable water; dug ponds are excluded from spots). A spot is a WATER tile with non-water tiles (dry land OR an existing bridge) on BOTH opposite sides, up/down or left/right, which excludes map corners and the middle of wide water by construction (a bridge extends over wide water one tile at a time). Max `MAX_BRIDGES` (8) per game, `BRIDGE_PRICE` (300 .. 16000, 8 entries) rises each time. Bridging turns the tile into an EMPTY tile in the grid (so bears and foxes walk over it, pockets stay connected through it) but it is remembered in `bridges`, and nothing can be placed, dropped or previewed there (`place`, `preview`, `moveLegal`); `freeCount` (empty tiles that are not bridges) replaces `emptyCount` in game-over and "board full" checks. `buyLand` remaps the indices; undo restores them. Rendering: bridged tiles still count as water in `drawWater` (the river runs under the planks) and get `.bridge .bh/.bv` planks. Long bridge (`longBridgeCells`, `longBridgeIncome`, `LONG_BRIDGE_MIN` 3, `LONG_BRIDGE_DIV` 400): bridged tiles that sit in a straight row or column run of 3 or more pay `max(1, round(PRICE[top] / 400))` coins per tile per tick every `place` (x `speed`, nothing while paused; event `bridgepay` with `coins`, `each`, `tiles`, `at`; computed from `bridges`, so no new state). They get `.cell.bridge.long` (accent glow) and `#bridgeNote` shows the count and income. - Calendar and banks, stage A (`state.tick`, `speed`, `banksBought`; code 22 `BANK`; `buyBank`, `bankPrice`, `bankCount`, `bankSlots`, `bankIncome`, `canBuyBank`, `isBankAvailable`, `calendar`): every `place` advances the clock by `speed` ticks (default 1; 0 pauses), `TICKS_PER_MONTH` 10, 12 months a year; the top line shows `📅 Y1 M3`. A bank is sold in the shop (button at the end of the item row, `.tool[data-tool="22"]`) once `unlockedTop >= BANK_MIN_TIER` (7, a village has stood), price `BANK_PRICE` 1500 / 3500 / 8000 by the banks held NOW (`bankSlots`: board + cur / next / reserve; `banksBought` is only a statistic), so merging three into cash starts the ladder again; at most `MAX_BANKS` (3) on the board counting the ones in cur / next / hold. `buyBank` makes it the current item like `buy` (old current -> next, old next dropped); it is placed with `place` like any item, can NEVER be stored (`swap` refuses while `cur === BANK`; swapNext is fine). It is a dead tile for animals (not roaming, a wall; not mauled) but the mover CAN carry an unlocked bank (`isMovable`; `moveLegal` refuses a locked one), so three banks can be lined up to merge into cash; `move` keeps the bank's place in `bankOrder`. Only the hammer breaks it. Every turn `place` pays `paying banks * bankIncome * speed` (`bankIncome` = `BANK_INCOME_RATE` 1% of `PRICE[top]` per tick, min 1; nothing while paused) with a `bankpay` event (`coins` total, `each` per bank, `ticks`, `banks`, `at` = the paying banks' cells: the UI floats each bank's own income over its own tile); a bank with a defaulted loan does not count. `NEXT[BANK] = CASH`, so three connected banks merge into cash on the tapped tile (no points or coins: the cash is the prize). `BANK` is in `QUEUE_ITEMS` (for validity) but `drawItem` never returns it. `migrate` defaults tick 0 / speed 1 / banksBought = banks on the grid; `validate` checks them and that no bank sits in the reserve. - Loans, stage B (`state.loans`: `{bank, at, tier, principal, rate, since, defaulted}` per loan, `state.bankOrder`: bank cell indices in the order they were placed; code 23 `SEIZED`; `borrow`, `repay`, `setSpeed`, `loanOptions`, `loanOwed`, `loanMonthsLeft`, `bankRate`, `lockedCells`): tap a bank (idle mode) -> `#bankDlg`. `borrow(state, bankIdx)` (free action) locks the dearest unlocked building (1..10, ties: lowest index) on one of the bank's four sides and pays `floor(PRICE[tier] / 2)` coins; the rate is `LOAN_RATE` 0.15 x 2^rank where rank is the bank's place in `bankOrder` (15 / 30 / 60%), stored in the loan. Debt = principal + `floor(principal * rate * months / 12)`, months whole and capped at 12. `repay` pays the debt, unlocks (the freed building / bank then runs `resolveAt`, so a trio merges at once and pays) or, for a defaulted loan, turns the seized lot back into EMPTY. Locking is the module-level `LOCK` set rebuilt by `dim(state)` from the loans: `group()` skips locked cells (no merging; `validate` skips them as group starts), `hammer` / `moveLegal` / mauling refuse them; a bank with any loan is locked, and a seized lot (`SEIZED`, a wall like water) is never hammerable or movable. `place` defaults every loan with `tick - since >= LOAN_TICKS` (120): the building is replaced by `SEIZED`, `defaulted = true`, event `default`; a bank with a defaulted loan pays no income. `settleBanks` keeps `bankOrder` in step after place / hammer / land / repay / migrate; `buyLand` remaps `bankOrder` and the loans. `isOver` also counts `loanEscape` (a defaulted loan the player can pay, or a loan that would buy the hammer), and `buy*` / `place` call it, so a full board with such an escape is not over. `setSpeed(state, 0..3)` sets ticks per turn (0 pauses everything: income, interest, deadlines); the `#speedLink` (visible once there is a bank or a loan) cycles 1x, 2x, 3x, paused. UI: `.cell.locked` padlock, `.cell[data-c="23"]` hatched grey, `#loanLine` pill (tap = open the first loan's bank), `lockedNow` in game.js feeds `targetOk` for the hammer / mover. `validate` checks loan indices, adjacency, terms, one seized lot per defaulted loan, the bank order and at most 4 loans per bank.
