# Triple Three (emoji)

Single-file merge-puzzle game (a free hobby project inspired by the classic genre, with its own name, code and emoji art): 6x6 board, place the "next" item, 3+ orthogonally connected identical items merge into the next tier on the tapped tile, bears wander and get trapped into tombstones -> churches. Plain HTML/CSS/JS, no framework, no runtime deps, installable PWA. Spec: `docs/GAME_BRIEF.md`.

## Layout
- `src/logic.js` - pure game logic (UMD: `require` in Node, global `TT` in the browser). State is plain JSON: `{ver, wild, map, w, h, land[], top, grid[w*h], cur, next, hold, score, coins, stock, milestone, turn, over, rng, seed, undo}`. `place(state, idx)` -> `{state, events}` or `null`; `swap`, `undo`, `validate`, `preview` (pure what-if for a placement), shop: `buy(state, item)` -> state, `hammer`, `trap` (kills a bear or fox into a tombstone), `move(state, from, to)` (mover: carries one non-animal item to an empty tile and merges it there; `previewMove` is the pure what-if), `buyLand(state, side)`, `open` (collect treasure/cash) -> `{state, events}` (all free actions, cost coins; prices/earnings in `PRICE`/`COIN`/`LAND_PRICE`). Everything is deterministic from `seed` (mulberry32; its state lives in the game state so undo/replay is exact). The board size is per state: the module-level `W/H/N` are set by `dim(state)` at the top of every public function (the exported `W/H/N` are only the starting 6x6).
- Codes: 0 empty, 1-10 building chain (grass, bush, tree, camp, hut, house, village, school, hospital, mall), 11 cash (final; tap to collect `CASH_COINS`), 12 bear, 13 tombstone, 14 church, 15 cathedral, 16 crystal, 17 treasure (final; tap to open for `TREASURE_COINS`), 18 fox, 19/20 a growling / angry bear (Wild bears games only; use `TT.isBear(code)` for "is a bear", never `=== TT.BEAR`), 21 water (map tile, see Maps). Use the named exports (`TT.BEAR`, `TT.CHURCH`, ...) in code and tests, never the numbers.
- `src/game.js` - UI: placement (Preview toggle, `tt-preview`; mouse: hover previews and ONE click places; touch: tap to preview, tap again to confirm), reserve tray (left of Place, the swap slot), shop (scrollable item row built by `buildShop`, trap/hammer/land row), hammer mode, one-level undo (there is no hints feature any more), animations driven by the `events` list, ambient critters (decorative only, never in the state; each critter is bound to ONE tile and only wanders inside it, re-homed on another matching tile if its tile vanishes), localStorage save (`tt-save`) and best score (`tt-best`). The board is rebuilt when `state.w/h` change. `#seed=N` in the URL forces a reproducible game. `window.ttDebug` is a read-only hook for tests.
- `src/style.css`, `src/index.html` - templates with `/*INLINE_...*/` placeholders.
- `build.js` - inlines everything into `dist/index.html`, writes manifest + service worker (cache name = content hash).
- `gen/icons.js` - PWA icons into `dist/` (pure Node PNG writer, no Pillow).
- `test/test.js` - logic tests + 400-game random fuzz (state valid after every turn, games terminate).
- `test/ui_test.py` - Playwright mobile-viewport test: PWA checks, plays seeded random turns (with swaps/undos) to game over, asserts valid state and DOM == state after every action.

## Commands (run from the project root)
```
node test/test.js          # must print "OK: N logic tests passed"
node build.js              # dist/index.html (self-contained) + manifest + sw.js
node gen/icons.js          # icons into dist/ (run after build)
python test/ui_test.py     # needs: pip install playwright && python -m playwright install chromium
                           # (preinstalled-browser setups: TT_CHROMIUM=/path/to/chromium python test/ui_test.py)
```
Serve `dist/` over https or localhost for the service worker (`python -m http.server -d dist`); opening the file directly also works but skips the PWA parts.

## Rules when changing things
- Changing logic: `node test/test.js`, rebuild, `python test/ui_test.py`. Keep `validate()` in sync with any new invariant.
- All randomness must go through the state's `rng` (never `Math.random` in logic) or replays/undo break.
- Decisions the brief left open: crystal acts as the best item kind that merges where dropped, otherwise waits as a wildcard; mall trio -> cash (final tier, collectible); bears and foxes come only from the item queue; one-level undo (costs coins); swap is a free action.
- Shop/coins: merges pay `(group-2)*COIN[tier]`; `buy` makes the item current and pushes the old current to `next` (old next is dropped); `hammer` clears any tile. `buy` refuses a purchase that would leave a full board unrescuable.
- Crystal choice (`crystalTier`): every kind the crystal could stand in for that makes a 3+ group is played out on a scratch copy INCLUDING the cascade (a camp trio makes a hut that may join two huts into a house), and the kind with the most points wins (then coins, then the `CRYSTAL_AS` order). It is not 'highest tier first'.
- Crystal: a crystal that cannot merge when placed stays as a wildcard and is re-checked after every placement (`settleCrystals`); `validate` asserts no crystal is left that could merge. A group of 4+ merges all its members into ONE next-tier item (only points/coins scale with size). Three or more connected crystals that have no tier to stand in for merge into ONE treasure on the tapped tile (`resolveAt` special-cases `CRYSTAL`; it pays no points or coins, the treasure is the prize; `validate` flags an unmerged gem trio and `migrate` settles every save).
- Shop limits: `stock` per item (`START_STOCK`; crystal starts at 0), each purchase/hammer/trap uses one; score milestones (`MILESTONES`, `milestoneScore(n)`) add `RESTOCK` and emit an `unlock` event. Game over = full board and no usable hammer (coins >= price AND stock > 0). Undo costs `UNDO_COST` coins, taken from the restored snapshot (`canUndo`). The snapshot (`state.undo`, one level) is taken by `place` AND by `move` / `hammer` / `trap` (`snapshot(state)`), so Undo reverts the last placement or the last mover / hammer / trap use (a tool use replaces an older placement snapshot); other free actions (buy, land, bridge, pond, bank, loans) do not take a snapshot and are reverted only together with the step before them. Old saves are upgraded by `migrate()`.
- Crystal can stand in for the bear chain too (cathedral > church > tombstone, then mall..grass); it is re-checked after placements, bear moves and traps.
- Bear trapping is per pocket (connected area of empty cells + bears, see `moveBears`): a bear dies only when its whole pocket has no empty cell, so bears sharing a pocket with room never die (a boxed-in one waits for its neighbour to move). When trapped tombstones merge, the cell just played goes first, so the church forms where the last bear was placed.
- Building chain (v2): 🌱 🌿 🌳 🏕️ 🛖 🏠 🏘️ 🏫 🏥 🏬 -> 💵 (collectible). Points x3 per tier, coins ~x2 per tier. Old (version-1) saves have other codes: `migrate()` remaps them (`V1_CODE`) and settles groups that the old final tier left unmerged. New state fields need a `migrate()` default and a `validate()` check; `migrate()` also fills any `START_STOCK` key a save lacks, so new shop items never invalidate a live save.
- Animals (`moveBears`): trapping is per pocket (connected empty cells + bears + foxes). A pocket with no empty cell turns every bear AND fox in it into a tombstone: a fox walled in on all sides, cornered, or sharing a box whose last free tile was just filled, and a fox on a full board all die the same way. A fox that is not trapped never walks, it warps to a random empty cell anywhere that still leaves it room (`landsWithRoom`: a warp never lands in a hole that would trap it at once; sealing it in later is the player's doing). Trapped animals on the same turn merge starting from the cell just played. The trap item kills a bear or fox anywhere.
- Shop pricing: `stock` per item; while it lasts the price is `PRICE`, past zero it doubles for every purchase (`priceOf`; stock goes negative = debt, milestone restocks pay it back). Hammer/trap/mover just run out (mover: `PRICE.move`, stock 1, +1 per milestone, free action, cannot carry bears or foxes, its drop merges like a placement). A building tier above tree is sold once one has stood on the board (`state.top`, `unlockedTop`); the crystal needs the first milestone. Restocks skip tiers that are not unlocked yet.
- Land: `buyLand(state, 'top'|'bottom'|'left'|'right')`, each side once, `LAND_PRICE` rises, adds one row/column (indices shift, so never cache cell indices across a land purchase). The new strip is empty land except where the old edge tile next to it is water (or a bridged tile): there the water carries on, so a river keeps running off the map. A strip can therefore add no free tile, so `buyLand` recomputes `over` with `isOver`. Game over = full board, no usable hammer AND no affordable land. Undo reverts a land purchase made since the snapshot (and refunds it).
- Name: the game is called Triple Three (renamed from เกมสามหมี / Three Bears at the owner's request). Keep the name consistent in UI, manifest, docs, comments and the service-worker cache name; do not use the name of the original game it is inspired by.
- Service worker is cache-first; the page reloads once when a new version takes over. After a rebuild, hard-refresh (Ctrl+Shift+R) to see changes.
- Icons are chosen by the owner (the plant tiers 🌱 🌿 🌳 are the summer look and change with the season, see Seasons): 🌱 🌿 🌳 🏕️ 🛖 🏠 🏘️ 🏫 🏥 🏬 💵. Do not swap similar-looking ones (🏡 looked too much like 🏠).
- Roadmap notes (bank, locked tiles, calendar, pond-style dead tiles) are in `docs/IDEAS.md`.
- The board is one plain grass field (continuous texture on `#board`, transparent tiles, faint tile edges). Do not bring back the alternating checkerboard tint.
- Animals on/off (per game, `state.bears` / `state.foxes`, both default true; chosen in the New game dialog (Bears: Classic / Wild / No bears; Foxes: on / off), remembered in `tt-bears` / `tt-foxes`; old saves get both true in `migrate`): `drawItem` turns a switched-off animal's draw into grass (same rng draws, so games with both on replay exactly as before). `wild` is only ever true with bears on. `validate` rejects a switched-off animal on the board / in cur-next-hold, and graves when both are off (calm mode). The trap tool is hidden in calm games (and its tour step skipped). Best scores get `-nobears` / `-nofox` suffixes. `startNew(seed, {wild, map, bears, foxes})` in game.js.
- Wild bears (per-game option, `state.wild`, chosen in the New game dialog, remembered in `tt-wild`; classic games and every old save are `wild: false` and never see codes 19/20, `validate` enforces it; best scores are separate: `tt-best` / `tt-best-wild`). A bear that cannot step because it is boxed in while its pocket still has room (a sealed bear still dies at once) escalates: boxed 1 turn -> 19 growling, 2 turns -> 20 angry, the 3rd boxed turn it mauls ONE adjacent tile of tier 1..`MAUL_MAX` (grass..hut) one tier down (grass is destroyed = an escape hole; the lowered tile merges if it completes a group) and starts over as a calm bear (12). A bear that walks resets to 12. Houses and everything above, tombstones, churches, cash are never mauled. The stage lives in the cell code, so no per-bear counters are stored.
- Wild bears also breed (`breed`, called from `moveBears` in wild games only): a pocket of at most `BREED_MAX_POCKET` (6) tiles holding 2+ bears and 2+ empty tiles has a `BREED_CHANCE` (10%) each turn of a calm cub appearing on one of its empty tiles, so a cub never takes the last free tile; never more than `BREED_MAX_BEARS` (8) bears on the board. Crowded pens are what makes bears wait boxed in long enough to maul.
- Island (`state.map === 'island'`; `state.reclaimed`; `reclaimSpots`, `reclaimPrice`, `canReclaim`, `buyReclaim`, `MAX_RECLAIM` 28, `RECLAIM_PRICE` 100 rising x1.2): the shop tool `#reclaimBtn` (`data-tool="reclaim"`, mode `'reclaim'`, hidden on other maps) turns a natural sea tile that touches a land tile (not water / seized / bridged; never a dug pond, never a corner of the ring until a neighbour is land) into EMPTY ground, a free action like bridge / pond; glowing `.spot` tiles show where. `isOver` also counts `canReclaim` (a full board with coins for the sea is not over). Bridges are never offered on the island (`bridgeSpots` returns []). Lake quests there count only the ponds you dug (`lakeGrid` ignores the sea ring), otherwise two ponds beside the ring would pay a 2x2 lake. `migrate` defaults `reclaimed` 0, `validate` allows it only on an island (and requires the 8x8 size); the TOUR has a Reclaim step (`when` island) and the Land step is skipped on the island. The miniature cards set their grid size from the generated board (`miniMap`, 8x8 for the island).
- Treasury (`tt-treasury` in localStorage, NOT in the game state; `TT.treasuryGain`, `treasuryAfter`, `TREASURY_SHARE` 2%, `TREASURY_CAP` 1000; `state.boost` = coins taken from it at the start, `newGame(seed, {start})`): leaving a game (`startNew`: a finished game, or New game on a running one) saves 2% of its coins (`treasuryNow` in game.js is the treasury after leaving the game on screen; an UNPLAYED game with a boost gives its starting coins back), and the New game dialog spends None / Half / All of it (`tt-take`, default all) as extra starting coins (`start`, capped at the cap; `coins = START_COINS + start`). A `#seed=` link never takes treasury coins. The game-over card shows the pending gain (`#overTreasury`). Games with `boost > 0` have their own best-score board (`-boost` suffix in `bestKey`) and say so in `modeLabel`. `migrate` defaults `boost` 0, `validate` bounds it. `ui_test.py` pins `tt-take` to none via an init script (the real default takes the whole treasury).
- Maps (`state.map`, chosen with the bear mode in the New game dialog, remembered in `tt-map`; best scores are per map and mode: `tt-best` for easy+classic, `tt-best-<map>[-wild]` otherwise): `easy` plain field (uses NO rng, so classic seeds replay as ever), `standard` 5 random grass/bush/tree that never form a group, `medium` a fixed winding river (`MEDIUM_WATER`, splits the field in two until a bridge exists), `hard` three random ponds (6..9 water tiles, the land stays one connected piece; the rng draws make them reproducible per seed), `island` the biggest board (8x8, `ISLAND_SIZE`, all four `land` sides already bought, so `buyLand` is refused and the land buttons are hidden) with a ring of sea (28 water tiles) around the 6x6 field, no rng in the generator (see Island). Water (code 21) is just a wall: not EMPTY (so it never counts as a free tile or a landing spot), not hammerable, not movable, not mergeable, animals cannot enter it; land purchases keep it (indices shift). Old saves are `easy`.
- Queue balance: `WEIGHTS` grass 61 / bush 16 / tree 6 / bear 12 / crystal 3 / fox 2; the crystal costs `PRICE[16]` (300; it was 50 at 4%, then 750 at 2%, which the owner found too dear and too rare). `drawItem(s, events)` also rolls `TRAP_DROP` (3%) on real turns (only when `events` is passed and the game has animals): +1 `stock.trap` and a `bonus` event (UI toast). The roll is an extra rng draw per turn, so queues differ from games made before this change (saves are unaffected: they store the state).
- New game sample maps: each map card (`.mapcard`) holds a `.mini` 6x6 thumbnail built by `miniMap(map, seed, el)` from the REAL generator (`TT.newGame(seed, {map})`, fixed seeds in `SAMPLE_SEEDS` / `CARD_SEED`), and `#mapSamples` lists examples of the selected map (3 for Standard / Hard, 1 for the fixed Easy / Medium / Island). When a map type is added, add its seeds and note.
- Lucky drops (`luckyTier`, inside `drawItem`): once `state.top` is at least 5, the next item is sometimes a camp / hut / house (tier 4 up to `min(top-1, 6)`, weights 3:2:1 for lower tiers first) with `LUCKY_RATE` per map (easy 6%, standard 4%, medium 3%, hard 0). The extra rng draws only happen when a drop is possible, so early games and the whole Hard map draw exactly the sequence they always did.
- Water look: the blue is ONE soft SVG layer under the tiles (`drawWater` in game.js: blurred + thresholded rects so neighbouring water tiles fuse, corners round off, a sandy bank blends into the grass, ripples drift; water touching the board edge is extended past it so rivers run off the edge). The water tiles themselves are transparent and only refuse taps. Swans and fish are critters bound to water tiles like the other critters.
- Bridges (`state.bridges`: indices of bridged water tiles; `bridgeSpots`, `buyBridge`, `bridgePrice`, `canBridge`): a shop tool, a free action; the button (`#bridgeBtn`) is only shown while a spot exists or a bridge has been built (never on maps without crossable water; dug ponds are excluded from spots). A spot is a WATER tile with non-water tiles (dry land OR an existing bridge) on BOTH opposite sides, up/down or left/right, which excludes map corners and the middle of wide water by construction (a bridge extends over wide water one tile at a time). Max `MAX_BRIDGES` (5) per game, `BRIDGE_PRICE` rises each time. Bridging turns the tile into an EMPTY tile in the grid (so bears and foxes walk over it, pockets stay connected through it) but it is remembered in `bridges`, and nothing can be placed, dropped or previewed there (`place`, `preview`, `moveLegal`); `freeCount` (empty tiles that are not bridges) replaces `emptyCount` in game-over and "board full" checks. `buyLand` remaps the indices; undo restores them. Rendering: bridged tiles still count as water in `drawWater` (the river runs under the planks) and get `.bridge .bh/.bv` planks. Income from crossings is not built yet (see `docs/IDEAS.md`).
- Ponds and lake quests (`state.ponds`: indices of dug ponds, `state.lake`: quests done 0..3; `buyPond`, `pondPrice`, `canPond`, `pondPoints`, `bestLake`; `MAX_PONDS` 16, `POND_PRICE` 60 rising x1.3: 60, 80, 100, 130, ... 3070; a 2x2 lake costs 370 in total, 3x3 1920, 4x4 13120): a shop tool on every map, a free action. `buyPond(state, idx)` turns an EMPTY non-bridge tile into WATER (permanent: not hammerable/movable, never a bridge spot) and refuses if fewer than 2 free tiles would be left (it never takes the last one). Every real turn `place` pays `ponds x ceil(BASE[top] / 20)` points AND `pondCoins` = `ponds x max(1, round(PRICE[top] / POND_COIN_DIV))` coins (`POND_COIN_DIV` 400; event `pondpts` with `points` and `coins`, before `grantMilestones`). Pond income and lake bonus points go into `state.bonusScore` as well as `score`: shop restocks (`grantMilestones`, `validate`, `migrate`) use `milestoneProgress(s) = score - bonusScore`, so ponds can never flood the shop with free stock (they once did: thousands of restocks per turn late in a game). Lake quests (`LAKE_SIZES` 2,3,4; bonus `BASE[top] * LAKE_BONUS` 30/100/300 points PLUS `LAKE_COINS` 200/1200/8000 coins, once each, event `lake` with `points` and `coins`): the pond that completes a k x k block of WATER containing it (natural water counts) pays the next quest. `buyLand` remaps `ponds` like `bridges`; `migrate` defaults `[]` / 0; `validate` checks every pond index is WATER. UI: tool `#pondBtn` (mode `'pond'`, same flow as bridge), lily pad on `.cell.pond`, `#pondNote` shows progress, and `#questLine` (in `.topinfo`, tap = open the shop) always shows the next lake quest. The shop's tool row is 5 columns (`.tools.util`), the land buttons on their own row.
- Calendar and banks, stage A (`state.tick`, `speed`, `banksBought`; code 22 `BANK`; `buyBank`, `bankPrice`, `bankCount`, `bankSlots`, `bankIncome`, `canBuyBank`, `isBankAvailable`, `calendar`): every `place` advances the clock by `speed` ticks (default 1; 0 pauses), `TICKS_PER_MONTH` 10, 12 months a year; the top line shows `📅 Y1 M3`. A bank is sold in the shop (button at the end of the item row, `.tool[data-tool="22"]`) once `unlockedTop >= BANK_MIN_TIER` (7, a village has stood), price `BANK_PRICE` 1500 / 3500 / 8000 by the banks held NOW (`bankSlots`: board + cur / next / reserve; `banksBought` is only a statistic), so merging three into cash starts the ladder again; at most `MAX_BANKS` (3) on the board counting the ones in cur / next / hold. `buyBank` makes it the current item like `buy` (old current -> next, old next dropped); it is placed with `place` like any item, can NEVER be stored (`swap` refuses while `cur === BANK`; swapNext is fine). It is a dead tile for animals (not roaming, a wall; not mauled) but the mover CAN carry an unlocked bank (`isMovable`; `moveLegal` refuses a locked one), so three banks can be lined up to merge into cash; `move` keeps the bank's place in `bankOrder`. Only the hammer breaks it. Every turn `place` pays `paying banks * bankIncome * speed` (`bankIncome` = `BANK_INCOME_RATE` 1% of `PRICE[top]` per tick, min 1; nothing while paused) with a `bankpay` event (`coins` total, `each` per bank, `ticks`, `banks`, `at` = the paying banks' cells: the UI floats each bank's own income over its own tile); a bank with a defaulted loan does not count. `NEXT[BANK] = CASH`, so three connected banks merge into cash on the tapped tile (no points or coins: the cash is the prize). `BANK` is in `QUEUE_ITEMS` (for validity) but `drawItem` never returns it. `migrate` defaults tick 0 / speed 1 / banksBought = banks on the grid; `validate` checks them and that no bank sits in the reserve. Stage B (loans) below.
- Loans, stage B (`state.loans`: `{bank, at, tier, principal, rate, since, defaulted}` per loan, `state.bankOrder`: bank cell indices in the order they were placed; code 23 `SEIZED`; `borrow`, `repay`, `setSpeed`, `loanOptions`, `loanOwed`, `loanMonthsLeft`, `bankRate`, `lockedCells`): tap a bank (idle mode) -> `#bankDlg`. `borrow(state, bankIdx)` (free action) locks the dearest unlocked building (1..10, ties: lowest index) on one of the bank's four sides and pays `floor(PRICE[tier] / 2)` coins; the rate is `LOAN_RATE` 0.15 x 2^rank where rank is the bank's place in `bankOrder` (15 / 30 / 60%), stored in the loan. Debt = principal + `floor(principal * rate * months / 12)`, months whole and capped at 12. `repay` pays the debt, unlocks (the freed building / bank then runs `resolveAt`, so a trio merges at once and pays) or, for a defaulted loan, turns the seized lot back into EMPTY. Locking is the module-level `LOCK` set rebuilt by `dim(state)` from the loans: `group()` skips locked cells (no merging; `validate` skips them as group starts), `hammer` / `moveLegal` / mauling refuse them; a bank with any loan is locked, and a seized lot (`SEIZED`, a wall like water) is never hammerable or movable. `place` defaults every loan with `tick - since >= LOAN_TICKS` (120): the building is replaced by `SEIZED`, `defaulted = true`, event `default`; a bank with a defaulted loan pays no income. `settleBanks` keeps `bankOrder` in step after place / hammer / land / repay / migrate; `buyLand` remaps `bankOrder` and the loans. `isOver` also counts `loanEscape` (a defaulted loan the player can pay, or a loan that would buy the hammer), and `buy*` / `place` call it, so a full board with such an escape is not over. `setSpeed(state, 0..3)` sets ticks per turn (0 pauses everything: income, interest, deadlines); the `#speedLink` (visible once there is a bank or a loan) cycles 1x, 2x, 3x, paused. UI: `.cell.locked` padlock, `.cell[data-c="23"]` hatched grey, `#loanLine` pill (tap = open the first loan's bank), `lockedNow` in game.js feeds `targetOk` for the hammer / mover. `validate` checks loan indices, adjacency, terms, one seized lot per defaulted loan, the bank order and at most 4 loans per bank.
- Phone layout (thumb reach): the top holds the **New game** button (top-left), score / best / coins, and the `.topinfo` line (turn and seed, then How to play · Item guide · 📳 Haptics); then free space; then ONE row with **Reserve | Place | ⇄ | Next** right above the map, which is pushed down (`margin-top: auto`, board centre about 60-65% down the screen); under the map the note line (`.noterow`, fixed height so nothing jumps when the "✕ tool" cancel chip `#toolCancel` appears), then the bottom row **Shop | Preview | Undo** (`.actions`, within thumb reach). `.side` is `display: contents` on phones so its children can be ordered with `order`. The shop (item row, trap / hammer / mover / bridge, land) is a bottom-sheet pop-up (`#shopSheet`, opened by `#shopBtn`, closed by its X, a tap outside, Escape, or any shop action). On wide screens (the `min-width: 900px` media block) the sheet is shown inline in the side column and the Shop button is hidden. In `ui_test.py` use `shop_tap(page, selector)` / `open_shop(page)` for anything inside the shop.
- Swapping: `swap` (the Reserve tray) exchanges the current item with the stored one, `swapNext` (the round ⇄ button between Place and Next, `#swapBtn`, or tapping the Next slot, `#nextBtn`) exchanges the current and the next item. Both are free actions: no turn, no coins; `swapNext` also draws no random numbers, so it is just a choice of order.
- First-run guided tour (`TOUR` in game.js, `#tour`): starts on the very first game (`tt-seen-help` not set, turn 0), from "How to play" (`#helpTour`), and ends with Skip / Done / Escape (which set `tt-seen-help`). Each step spotlights a control (`target` selector, several matches are unioned), puts a card where it fits, and `sheet: true` steps open the shop sheet first. `when()` drops steps that do not apply (no bridge button on maps without water, no Shop button on wide screens). **When you add a control or tool, add a `TOUR` step for it** (and keep the Item guide / help text in step); `ui_test.py` walks the whole tour and checks every card is on screen.
- Seasons (cosmetic only, never in the state): `data-season` on `<html>` (`tt-season`: auto | spring | summer | autumn | winter; auto follows the calendar month) swaps the CSS tokens (`--bg --g1 --g2 --line --edge --deco --w1..w3 --bank`); the water SVG reads `--w*` / `--bank` through `style="...:var()"`. `applySeason()` also fills `#seasonFx` with a few falling petals / leaves / snowflakes (not in summer, hidden under `prefers-reduced-motion`). The cycle link `#seasonLink` is in the `.topinfo` line. Natural items follow the season too (owner's request): `PLANTS` swaps the emoji of tiers 1-3 (summer 🌱🌿🌳, spring 🌻💐🌸, autumn 🍂🍄🪾, winter ❄️🎁🎄; 🪾 is from 2023: `glyphOk` draws it on a canvas, and falls back to 🍁 when it has no coloured pixel, i.e. the font lacks it) and `CRITTERS` the animals around the homes / graves / water. EVERY place that shows an item uses `em(code)` (never `TT.EMOJI[...]` in game.js; the logic names stay grass / bush / tree), and a season change rebuilds the shop, Item guide, New game thumbnails and critters. The wild animals have seasonal skins too (`SKINS`: summer and spring 🐻 / 🦊, autumn 🐗 boar / 🦝 raccoon, winter 🐺 wolf / 🐇 rabbit; `em()` maps BEAR, the growling / angry stages and FOX, `nm()` the names, e.g. 'angry wolf'); display only, the logic and its codes are untouched, and the winter home critters are deer / birds so no rabbit is ambient there. - Version and updating: `build.js` hashes the built page (placeholder `__BUILD__`) into an 8-char id shown in How to play (`#buildId`) and used as the service-worker cache name. `#updateLink` ("Get the latest version") unregisters the service worker, deletes its caches and reloads; localStorage (saves, best scores, settings) is untouched, so it is the safe phone replacement for a hard refresh. Never tell players to "clear site data" (that erases the save).
- How to play is paged (`#helpPages`, five `<section class="helppage">` topics: basics, animals, shop and items, maps and water, banks and loans; `showHelpPage`, `#helpPrev` / `#helpNext`, it always opens on page 1). **When you add a rule to the help text, put it on the page it belongs to** (or add a page). Links inside `.card` use the accent colour (the default blue is unreadable on the green card).
- Haptics: `vibrate()` (buzz on placing, merging, collecting, buying land) is gated by the `haptics` setting (`tt-haptics`, default on), switched with the "📳 Haptics" link in the `.topinfo` line; the link is hidden where `navigator.vibrate` does not exist (iPhones). Route any new buzz through `vibrate()`.
